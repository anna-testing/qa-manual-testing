| **A. Тестирование поиска магазинов (с верификацией через БД)** |  |
| 1. **Валидация условий активности кнопки "Поиск"** |  |  
| - Оба поля пусты - кнопка неактивна |  |  
| - Заполнено только название - кнопка активна (проверить SQL: `SELECT * FROM shops WHERE name LIKE '%введенное_название%'`) |  | 
| - Заполнен только тип - кнопка активна (проверить SQL: `SELECT * FROM shops WHERE type = 'выбранный_тип'`) |  |  
| - Заполнены оба поля - кнопка активна |  |  
| 2. **Точность отображения результатов** |  |  
| - Сравнить количество флажков на карте с количеством записей в БД для запроса |  | 
| - Проверить координаты 3 случайных флажков: совпадают ли с `latitude/longitude` в БД? |  |  
| - Поиск несуществующего названия - проверить отсутствие результатов в UI и пустой результат в БД |  |  
| 3. **Проверка истории поисков** |  |  
| - После успешного поиска проверить запись в таблице `search_history` |  |  
| - Ввести частичное совпадение предыдущего запроса - проверить подсказки из истории |  |  
| - Очистить кэш приложения - убедиться, что история сохраняется в БД |  |

| **B. Тестирование построения маршрута (с интеграцией БД)** |  |
| 4. **Активность кнопки "Построить маршрут"** |  |  
| - Сценарий 1: Выбран флажок магазина - проверить запись в `selected_shops` |  |  
| - Сценарий 2: Выбран тип - проверить запрос ближайшего магазина: sql SELECT * FROM shops WHERE type = 'выбранный_тип'ORDER BY ST_Distance(geopoint, :user_location) LIMIT 1 |  |
|  |  |
| 5. **Восстановление маршрута при перезапуске** |  |  
| - Прервать маршрут - перезапустить приложение - проверить: |  |  
| - Состояние в таблице `active_routes` |  |  
| - Автоматическое центрирование карты на маршруте |  |  
| -  Изменить данные магазина в БД - проверить обработку несуществующего маршрута |  |  
|  |  |
| 6. **Проверка алгоритма "ближайшего магазина"** |  |  
| -  Имитировать разные координаты пользователя  - проверить корректность выбора магазина |  |  
| -  Добавить в БД магазин ближе существующего  - проверить автоматическое обновление выбора |  |  
|  |  |
| **C. Тестирование геолокации и энергопотребления** |  |
| 7. **Управление точностью геоданных** |  |  
| -  Эмулировать 5% заряд батареи  - проверить: |  |  
|    - Запись в логах: `Geolocation accuracy reduced` |  |  
|    - Значение `is_precise = false` в таблице `location_settings` |  |  
|  -  Проверить поведение при построении маршрута с неточной геолокацией |  |  
|  |  |
| 8. **Интеграция геоданных с картой** |  |  
| -  Сравнить координаты пользователя на карте с данными в `current_locations` |  |  
| -  Проверить обновление маршрута при изменении местоположения (верифицировать через `route_updates`) |  |  
|  |  |
| **D. Тестирование карты и состояний** |  |
| 9. **Валидация области карты** |  |  
| -  Измерить размер области на разных устройствах  - должно быть ровно 50% |  |  
| -  Проверить поведение при смене ориентации экрана |  |  
|  |  |
| 10. **Работа с маршрутом** |  |  
| -  Построить маршрут  - проверить запись в `routes` с меткой времени |  |  
| -  Отменить через кнопку  - проверить статус `is_canceled = true` |  |  
| -  Попытаться отменить свайпом  - убедиться, что маршрут остается |  |
