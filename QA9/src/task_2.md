# Три основные инструмента криптографии:

| Инструмент     | Определение | Аналогия | Цель | Примеры |
|----------------|-------------|----------|------|---------|
| **Кодирование** | Процесс преобразования данных из одной формы представления в другую по открытому, заранее известному алгоритму. | Перевод текста с русского языка на английский.<br>Любой, кто знает английский, может его прочитать. | Обеспечение удобства хранения<br>или передачи данных<br><em>(без обеспечения секретности)</em>. | Base64<br>URL-encoding<br>ASCII<br>HEX |
| **Хеширование** | Процесс преобразования произвольных данных в строку фиксированной длины с помощью специальной математической функции.<br>Преобразование является <strong>односторонним</strong> (необратимым).<br>Ключевые свойства: детерминированность и лавинный эффект. | Отпечаток пальца — можно идентифицировать человека, но нельзя восстановить человека по отпечатку. | Проверка целостности данных<br>Хранение паролей<br>Создание цифровых отпечатков | MD5<br>SHA-1<br>SHA-256 |
| **Шифрование**  | Процесс преобразования данных в зашифрованную, нечитаемую форму с использованием специального алгоритма и ключа.<br>Процесс является <strong>обратимым</strong> при наличии правильного ключа. | Запертый сейф — только тот, у кого есть ключ, может открыть и получить содержимое. | Обеспечение конфиденциальности данных | AES<br>RSA<br>DES |


## Типы шифрования

| Тип шифрования | Определение | Ключевые особенности |
|----------------|-------------|----------------------|
| **Симметричное шифрование** | Используется один и тот же секретный ключ для выполнения как шифрования, так и расшифрования данных.<br>Отправитель и получатель должны заранее безопасным способом обменяться этим ключом. | • Один ключ для шифрования и дешифрования<br>• Высокая скорость работы<br>• Проблема безопасной передачи ключа<br>• Примеры: AES, DES, ChaCha20 |
| **Асимметричное шифрование**<br>(криптография с открытым ключом) | Используется пара ключей: открытый (public key) и закрытый (private key).<br>Открытый ключ доступен всем и используется для шифрования данных.<br>Закрытый ключ хранится в секрете у владельца и используется для расшифрования.<br>Данные, зашифрованные открытым ключом, могут быть расшифрованы только парным закрытым ключом. | • Два ключа: открытый и закрытый<br>• Решает проблему обмена ключами<br>• Медленнее симметричного шифрования<br>• Примеры: RSA, ECC, ElGamal |


### Сравнительная характеристика симметричного и ассиметричного шифрования

| Критерий | Симметричное шифрование | Асимметричное шифрование |
| --- | --- | --- |
| **Скорость** | Быстрее | Медленнее |
| **Ключи** | Один секретный ключ | Пара ключей (public/private) |
| **Безопасность** | Проблема распределения ключей | Безопасное распределение ключей |
| **Использование** | Шифрование больших данных | Шифрование ключей, цифровые подписи |

### Симметричное и асимметричное шифрование

| Характеристика | Симметричное шифрование | Асимметричное шифрование |
|-------------------------|--------------------------------------------------|--------------------------------------------------|
| **Плюсы** | • Высокая скорость работы<br>• Эффективные алгоритмы<br>• Меньше вычислительной мощности<br>• Подходит для больших объемов данных | • Решает проблему обмена ключами<br>• Не требует предварительной передачи ключа<br>• Обеспечивает цифровые подписи<br>• Обеспечивает аутентификацию |
| **Минусы** | • Проблема безопасной передачи ключа<br>• Компрометация ключа приводит к полной компрометации данных | • Медленнее симметричного шифрования<br>• Требует больше вычислительных ресурсов<br>• Не подходит для больших объемов данных |

На практике часто используют гибридные системы: асимметричное шифрование применяют для безопасной передачи сеансового ключа, а затем этим сеансовым ключом с помощью симметричного шифрования шифруют основные данные.

### Алгоритмы симметричного шифрования

| Категория               | Алгоритмы симметричного шифрования                              |
|-------------------------|-----------------------------------------------------------------|
| **Слабые (небезопасные)** | • **DES** (Data Encryption Standard):<br>  - Слишком короткий ключ (56 бит)<br>  - Взламывается полным перебором за разумное время<br><br>• **RC4** (Rivest Cipher 4):<br>  - Уязвимости в генерации ключевого потока<br>  - Предсказуем и небезопасен |
| **Безопасные (рекомендованные)** | • **AES** (Advanced Encryption Standard):<br>  - Золотой стандарт шифрования<br>  - Ключи 128/192/256 бит<br>  - Используется для защиты данных "совершенно секретно" в США<br><br>• **ChaCha20**:<br>  - Быстрый и безопасный алгоритм<br>  - Альтернатива AES<br>  - Оптимизирован для мобильных устройств и TLS |

### Алгоритмы хеширования

| Категория                   | Алгоритмы хеширования                              |
|-----------------------------|----------------------------------------------------|
| **Нерекомендованные (слабые)** | • **MD5**:<br>  - Серьезные уязвимости, позволяющие находить коллизии<br>  - Полностью скомпрометирован<br>  - Быстро находится коллизия<br><br>• **SHA-1**:<br>  - Небезопасен из-за атак нахождения коллизий<br>  - Поддержка прекращена крупными организациями<br>  - Не рекомендуется для новых систем |
| **Рекомендованные (стойкие)** | • **SHA-256/SHA-384/SHA-512**:<br>  - Часть семейства SHA-2<br>  - Надежные и широко применяемые<br>  - Используются в blockchain (Bitcoin)<br><br>• **SHA-3 (Keccak)**:<br>  - Новейший стандарт хеширования<br>  - Основан на другом математическом подходе<br>  - Стойкий к потенциальным атакам на SHA-2 |
