### Схема работы HTTPS-протокола (TLS/SSL handshake)
Шаги установки защищённого соединения:

1. **Клиент (браузер) отправляет серверу запрос с параметрами:**   
   - Поддерживаемые версии TLS (например, TLS 1.2/1.3)  
   - Список криптоалгоритмов для генерации ключей (шифры, хеш-функции)  
   - Случайное число - уникальный идентификатор сессии (Client Random)

2. **Сервер отвечает:**   
   - Выбирает оптимальный алгоритм шифрования (версию TLS)   
   - Генерирует Server Random для дальнейшей аутентификации   
   - **Сертификат сервера** (с публичным ключом и данными организации)  
   - (Опционально) Запрос сертификата клиента  

3. **Проверка сертификата**  
   Клиент-браузер:  
   - Проверяет подлинность и актуальность сертификата через центры сертификации (например, Let's Encrypt)  
   - Верифицирует домен и срок действия  
   - Удостоверяется, что сертификат отсутствует в списке отозванных (CRL) 

4. **Key Exchange - Обмен ключами**  
   - Клиент генерирует/создает временный ключ  **pre-master secret**  
   - Шифрует его открытым публичным ключом сервера - и передаёт в зашифрованном виде   

5. **Создаются сессионные ключи**  
   Обе стороны вычисляют:  
   - Общий **Master Secret** на основе PRF(Client Random + Server Random + Pre-Master Secret)  
   - Генерируют 4 ключа для:  
     - Шифрования исходящих/входящих данных  
     - Проверки целостности сообщений 

6. **Подтверждение безопасности**   
      - Клиент и сервер обмениваются зашифрованными тестовыми сообщениями  
    - При успехе начинается передача данных   

7. **Защищённая передача данных**  
   - Все анные шифруются симметричными ключами (AES-256, ChaCha20) 
   - Каждое сообщение содержит код аутентификации (HMAC).  

(Процесс занимает 300-500 мс.)

### Основные группы HTTP-кодов состояния
| Группа | Значение                  | Примеры кодов и их назначение                                                                 |
|--------|---------------------------|----------------------------------------------------------------------------------------------|
| **1xx** | Информационные            | 100 Continue (сервер готов принять тело запроса)<br>101 Switching Protocols (смена протокола, например, на WebSocket) |
| **2xx** | Успешные                  | 200 OK (стандартный успех)<br>201 Created (ресурс создан)<br>204 No Content (нет тела ответа) |
| **3xx** | Перенаправления           | 301 Moved Permanently (постоянный редирект)<br>302 Found (временный редирект)<br>304 Not Modified (контент не изменился) |
| **4xx** | Ошибки клиента            | 400 Bad Request (некорректный запрос)<br>401 Unauthorized (требуется аутентификация)<br>403 Forbidden (доступ запрещён)<br>404 Not Found (ресурс не существует) |
| **5xx** | Ошибки сервера            | 500 Internal Server Error (общая ошибка сервера)<br>502 Bad Gateway (проблема с прокси/бэкендом)<br>503 Service Unavailable (сервис недоступен)<br>504 Gateway Timeout (таймаут шлюза) |


#### Для тестировщика
- **4xx**:  
  - 400 - Проверить валидацию входных данных  
  - 403 - Протестировать RBAC (ролевой доступ)  
  - 429 Too Many Requests - Проверить rate limiting  

- **5xx**:  
  - 502/504 - Протестировать отказоустойчивость балансировщиков  
  - 503 - Симитировать перегрузку сервера  

#### Особые случаи 
- 451 Unavailable For Legal Reasons (блокировка по юридическим причинам)
