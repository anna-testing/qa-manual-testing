| Метод | Назначение |
|---|---|
| **GET** | Получить представление ресурса или список ресурсов без изменения состояния сервера. |
| **POST** | Создать новый ресурс или отправить данные для обработки на сервере. |
| **PUT** | Полностью заменить существующий ресурс указанным представлением. |
| **PATCH** | Частично обновить существующий ресурс, изменив только указанные поля. |
| **DELETE** | Удалить указанный ресурс. |
| **HEAD** | Получить только метаданные ответа (заголовки) для ресурса, без тела (как GET, но без содержимого). |
| **OPTIONS** | Запросить поддерживаемые сервером методы и другие доступные параметры для указанного ресурса (CORS/описание возможностей). |

| Метод | Описание | Общие коды ответов | Типичный пример использования |
|---|---|---:|---|
| **GET** | read - Получает представление ресурса или список ресурсов; не должен изменять состояние сервера (идемпотентен и безопасен). | **200**, 304, 404 | Получить профиль пользователя: GET /users/123 |
| **POST** | create - Отправляет данные на сервер для создания нового ресурса или запуска обработки; не обязательно идемпотентен. | **201**, 200, 400, 409 | Создать новый пост: POST /posts с телом JSON |
| **PUT** | update - Полностью заменяет существующий ресурс указанным представлением; идемпотентен (повторные запросы дают тот же результат). | **200**, **204**, 400, 404 | Обновить профиль целиком: PUT /users/123 с полным JSON объекта |
| **PATCH** | Частично обновляет ресурс, изменяя только указанные поля; обычно не идемпотентен, но может быть. | **200**, **204**, 400, 404 | Обновить email: PATCH /users/123 { "email": "a@b.com" } |
| **DELETE** | Удаляет ресурс; идемпотентен (повторный DELETE часто возвращает 404 или 204). | **200**, **204**, 404 | Удалить комментарий: DELETE /comments/456 |
| **HEAD** | Запрашивает только заголовки ответа для ресурса (без тела) — полезно для проверки существования, типов и длины контента. | Аналогичные GET, но без тела (200, 404) | Проверить, изменился ли файл: HEAD /files/report.pdf |
| **OPTIONS** | Запрашивает поддерживаемые методы и другие возможности для ресурса; часто используется для CORS preflight. | **200**, 204 | Узнать поддерживаемые методы: OPTIONS /api/items  (в ответе Allow: GET,POST,OPTIONS) |


1XX — короткое подтверждение: сервер говорит «получил, работаю дальше», чаще используется для низкоуровневых шагов протокола.

2XX — всё ок: запрос выполнен, результат возвращён или создано то, что просили.

3XX — нужно перейти/доделать: клиент должен пойти по другому адресу или выполнить дополнительный шаг (перенаправления).

4XX — ошибка клиента: в запросе что‑то не так — неверный формат, нет прав или ресурс не найден.

5XX — ошибка сервера: проблема внутри сервера — он не смог корректно обработать даже правильный запрос.


Как расшифровывается JSON?
JSON — JavaScript Object Notation - это текстовый формат обмена данными, представляющий структуры данных в виде пар «ключ: значение» и массивов

| Формат | Преимущества JSON |
|---|---|
| XML | JSON короче и проще для передачи данных; легче парсится в большинстве языков; структура данных (объекты/массивы) ближе к типам в языках программирования; меньше шума от тегов; чаще используется в web‑API. |
| YAML | JSON более однозначен и прост для парсинга (меньше проблем с отступами и форматированием); меньшая площадь для ошибок безопасности при разборе (YAML поддерживает сложные типы и возможности выполнения); JSON более универсален для браузеров и большинства клиентов. |

Что такое JSON Schema? JSON Schema — формальный стандарт для описания структуры, типов и ограничений JSON‑документов.
Используется для валидации, документирования и генерации данных/форм. Позволяет задать, какие поля обязательны, их типы (string, number, object, array, boolean, null), паттерны, диапазоны, форматы (email, date-time) и т. п.


Что такое сериализация и десериализация в контексте JSON? 
**Сериализация** — преобразование объекта/структуры данных в строку JSON для хранения или передачи.
**Десериализация** — разбор JSON‑строки обратно в объект/структуру данных в памяти приложения.
