# Логи и логирование
### Уровни логов (Log Levels)
Уровни логов определяют важность или серьезность сообщения. В Android используется система уровней, унаследованная от ядра Linux и стандарта syslog. Для фильтрации в Logcat они имеют свои цветовые обозначения.

| Уровень (Метод) | Описание | Цвет в Logcat | Использование |
| :--- | :--- | :--- | :--- |
| **ERROR** (`Log.e()`) | **Ошибка.** Сообщения о критических проблемах, которые приводят к неработоспособности части функционала или всего приложения. Это исключения (Exceptions), которые не были обработаны, или серьезные сбои. | **Красный** | Для фиксации ошибок, которые требуют немедленного внимания разработчика. |
| **WARNING** (`Log.w()`) | **Предупреждение.** Сообщения о потенциально проблемных ситуациях, которые пока не привели к ошибке, но могут вызвать проблемы в будущем. Например, использование устаревшего (deprecated) API. | **Оранжевый** | Для указания на нежелательные или подозрительные состояния, которые не являются критическими. |
| **INFO** (`Log.i()`) | **Информация.** Сообщения, которые фиксируют ключевые события в работе приложения, подтверждающие, что всё работает как ожидалось. Например, "пользователь успешно авторизован", "данные загружены". | **Зеленый** | Для общего информационного вывода, полезного для понимания потока выполнения программы. |
| **DEBUG** (`Log.d()`) | **Отладка.** Подробные сообщения, полезные во время разработки и отладки для понимания потока выполнения программы. Эти логи обычно не включаются в релизные сборки. | **Синий** | Для вывода значений переменных, отслеживания выполнения методов, диагностики. |
| **VERBOSE** (`Log.v()`) | **Подробный вывод.** Наиболее подробный уровень логирования. Содержит максимум информации о работе приложения. Используется для самого детального анализа поведения. Как и DEBUG, обычно отключается в релизе. | **Черный/Серый** | Для всего остального, когда нужна максимальная детализация. |
| **ASSERT** (`Log.wtf()`) | **Критическая ошибка** (What a Terrible Failure). Уровень для сообщений о ситуациях, которые никогда не должны происходить. Самый высокий приоритет. Считается еще более серьезным, чем ERROR. | **Красный** | Для фиксации катастрофических сбоев, assertions. |

### Типы логов / Буферы (Log Types / Buffers)
В Android логи записываются в разные буферы (очереди) в зависимости от их происхождения. В Logcat можно выбрать, какой буфер показывать.
| Тип (Буфер) | Описание | Содержимое |
| :--- | :--- | :--- |
| **Main** (Основной) | **Основной буфер по умолчанию.** Содержит большинство логов от приложений и системы Android, которые не относятся к конкретным другим буферам. | Логи приложений (использующие класс `Log`), логи системы Android. |
| **System** (Системный) | Буфер для сообщений от операционной системы Android. | Сообщения от различных системных сервисов и процессов (`SystemServer`, `ActivityManager`, `WindowManager` и т.д.). |
| **Radio** (Радио) | Буфер для сообщений, связанных с телекоммуникационным стеком (модулем). | Очень низкоуровневые логи, связанные с сотовой сетью, телефонией, SMS, мобильным интернетом. |
| **Events** (События) | Буфер для системных событий, закодированных в специальном бинарном формате. | События, такие как сборка мусора (GC), запуск активностей, нажатия кнопок. Для чтения часто требуется утилита `android debug eventlog`. |
| **Kernel** (Ядро) | Логи ядра Linux. *Недоступны для прямого просмотра через стандартный `Logcat`.* | Низкоуровневые сообщения от драйверов оборудования, подсистемы питания, планировщика задач и т.д. |

### Механизмы записи логов (Logging Mechanisms)
Это способы, с помощью которых разработчик или система могут генерировать логи.

| Механизм | Описание |
| :--- | :--- |
| **Класс `android.util.Log`** | Основной и самый простой механизм для записи логов из Java/Kotlin кода приложения. Предоставляет статические методы для каждого уровня: `v()`, `d()`, `i()`, `w()`, `e()`. |
| **Класс `Log.println()`** | Низкоуровневый метод класса `Log`. Позволяет явно указать уровень, тег и сообщение в виде целого числа. |
| **Логирование в Release** | Кастомные решения для сбора логов на устройствах пользователей (например, для Crash Reporting). Логи пишутся в файл на устройстве или отправляются на сервер. |
| **Системный логгинг (`logcat` команда)** | Утилита командной строки `logcat`, входящая в состав Android SDK (Platform-Tools). Является основным инструментом для просмотра всех перечисленных выше буферов логов. |
| **Логирование в Нативное коде (C/C++)** | Для логирования из нативного кода (NDK) используется API **`<android/log.h>`**. Основные макросы: `__android_log_write`, `__android_log_print`, `__android_log_assert`. |
| **Логирование ядра (Kernel)** | Осуществляется с помощью функции `printk()` внутри кода ядра Linux. |
